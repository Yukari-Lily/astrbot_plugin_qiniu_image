# 设计说明

## 聊天方案与关键词入口

聊天出图恢复 1.3 的职责划分：主模型结合用户要求、已有上下文、人设及必要考据形成完整方案；优化器整理表达、校正事实、消除冲突，将适用风格与质量规则融合成执行提示词。用户明确要求优先，优化器不重新规划画面。

```text
聊天消息 → 主模型完整方案 → 图片解析 → 优化器融合风格与质量
                                     → integrated=true
                                     → 执行稿 + 必要图片约束
关键词消息 → 图片解析 → 原文方案 → integrated=false
                                → 原文 + 图片约束 + 全局质量段
                                              ↓
                                 图片生成 → 记录实际提交稿
                                              ↓ 审核拒绝
                                安全改写 → 按原入口方式提交
```

关键词维持原文直出，不经过主模型、正常优化或自动风格选择。聊天立即受理并后台发送，关键词等待并返回；两者共用任务登记、图片处理和错误处理。卸载时取消在途任务后关闭客户端。

## 数据与工具接口

保留 `draw_image(prompt, subject_info="", use_last_image=False, keep_layout=True)`。新绘图的 `prompt` 是完整方案；续画时是本轮修改。主模型可在用户允许的空间内设计姿势、镜头、服装、场景、光影与风格，但不扩大局部编辑范围。常见角色直接补全可靠身份，无法可靠识别时先搜索、阅读，再绘图。`subject_info` 只补充必要事实，不传完整人格规则或群聊，也不恢复与执行器冲突的 `context` 参数。

`DrawingRequest`、`ImagePlan`、`ImageRecord` 均为不可变快照。`ImagePlan.integrated` 标记执行稿是否已经融合视觉要求，默认为 false，正常优化结果为 true；该状态由插件设置，模型不能通过 JSON 切换。风格 ID 只用于记录和续画，不触发模板追加。

成功记录同时保存方案、图片用途、更新时间及 `submitted_prompt`（实际提交的完整字符串）。查询工具返回实际提交稿、风格、融合状态与图片用途。续画受理时取得上一稿快照，向优化器提供其正文和风格，剥离旧固定尾段与图片约束，由当前图片用途重新决定。主模型无需先查询或转抄底稿。

缓存按会话与用户隔离，最多 100 条，仅内存保存。生成成功才更新，失败不覆盖；生成成功不代表消息平台已成功投递。记录不含图片像素，精确编辑仍需用户发送或引用图片。

## 风格融合与提交

优化输入包含 `plan`、用于核对明确限制的 `user_message`、`subject_info`、上一稿及当前图片用途；不让短原话抹去主模型已形成的授权设计。原图只交给图片模型，文字优化器不看图。局部改图保留实际外观及未修改部分，参考创作按方案重建构图。

优化结果为 JSON `prompt`、`style` 和必要时的 `style_exception`，正文是一段具体、连贯的最终执行提示词。接受完整 JSON 代码围栏，拒绝空值、拒答、格式错误及非法风格 ID；不按风格名称全局删字，保留用户指定画出的文字。

预设文案和自动偏好以 1.3 的 `5020e13` 为基础，目录与优化输入同源。净色动画壁纸另设为低优先（-1），排序到末尾，仅限明确至少两名人物。明确点名的风格优先，但净色的多人限制同样适用；已有具体画风或完整视觉方案时不另套模板。缺少具体画风时选择相容项，多个适合时优先高偏好项。只吸收适用属性，倒立、悬浮、强透视和轮廓融合可以因不适用而舍弃，不能破坏既定姿态与结构可读性。

净色选择额外要求 `people_count` 为至少 2 的整数（拒绝布尔值、字符串），并提供 `people_evidence` 逐字引用方案、用户消息或上一稿中的多人依据。人数按本轮最终方案解释，不得为风格新增人物，不把镜像或同一人的别名重复计数；单人续画也不能沿用净色。插件校验结构、人数下限及引用来源，语义识别仍依赖模型。缺少依据或校验失败沿用有界重试，不能直接出图。人数随方案记录并写入日志，安全改写沿用人数与主体保持要求。

空风格允许 `preserve_image`、`preserve_previous`、`external`、`user_opt_out`、`preserve_plan` 和 `incompatible`；前两项校验图片和上一稿状态，其余由模型结合方案判断，不再要求 `style_evidence`。关闭风格时必须留空并记录 disabled，关键词记录 keyword。泛化质量词不构成具体画风。

`style_strength` 与全局质量规则在优化阶段使用。subtle 只借用少量特征，normal 使用核心视觉语言并删除冲突细节，strong 充分使用相容的构图、色彩和材质。必要结构、体积与光影不能为简化线条而牺牲。

`compose_prompt` 对聊天稿仅追加必要图片约束，不追加预设或质量段；关键词保留原有质量段追加。`plan_body` 保留对旧固定标题的兼容清理，重复拼装不叠加。历史风格段标题仅用于清理，不用于新模板生成。

## 重试、日志与图片处理

保留共享模型调用：每轮按 Provider 顺序尝试，失败先切备用，每模型最多三次；正常优化 120 秒，安全改写 45 秒。通过签名判断 system_prompt 支持情况，不因内部 TypeError 隐式重发。优化全部失败停止，不使用未经优化的方案降级出图。

只有首次明确 QiniuSafetyError 才进入安全改写。原模型第一层失败后，已配置 Grok 时先用首次实际提交稿调用 `grok-imagine-image-2.0`；失败后再用第一层改写稿调用 Grok。已有第一层改写直接复用，此前没得到可用改写时才重新请求第一层。两次 Grok 尝试失败或改写不可用，才接回原模型第 2～5 层；未配置 Grok 时保留原流程。第一层已进入安全流程后的非审核错误也可尝试 Grok。

聊天改写接收首次实际提交的完整提示词，保留安全的视觉设计；关键词仍改写原文。候选稿继承入口融合状态：聊天不重新套模板，关键词保留固定质量段。每级从首次方案开始，成功保存实际采用的稿件。首次网络、鉴权、限流和响应错误不触发安全改写。

INFO 记录优化正文、风格和留空原因，以及提交时的融合状态、风格强度、实际图像模型、质量、尺寸和图片用途。DEBUG 保留优化输入和完整提交提示词。

输入一次区分无图、可用图和确认存在但不可读图；优先当前消息，再取引用链与 OneBot get_msg。按当前 Bot 平台实例查询，保留旧接口、消息数组和 CQ 字符串兼容。关键词去重键含会话来源和消息 ID，TTL 为 20 秒。

响应只扫描一次，选定有效 Base64 或 URL 后独立处理，下载失败不重新生成。输入本地下载或解码限制 40 MB，支持 PNG、JPEG、WebP、GIF；输出限制 80 MiB，支持 PNG、JPEG、WebP。URL 交给上游时不预下载。编辑先使用 JSON，仅在 HTTP 400 明确要求 multipart 时回退文件上传。

实际图像模型、质量、尺寸、超时及并发设置保持现状，不恢复 1.3 的缺省模型；配置页仍默认 openai/gpt-image-2。

## 验证边界

2.1.0 按本次交付要求不新增或运行测试，不调用真实生成接口；以下是已有的验证方式。

运行 `python -m unittest discover -s tests -v` 验证方案传递、融合提交、关键词行为、风格留空、图片用途、幂等拼装、续画隔离、安全重试和响应处理。模型和图片服务均为 mock，不能据此认定画质改善。

真实对照需在 AstrBot 固定请求、图像模型、质量和尺寸，对 1.3 与修改版各生成至少三张，保存执行稿并比较人体连续性、构图和风格融合。重新加载插件刷新工具说明，必要时使用新会话避免旧工具调用习惯影响对照。
