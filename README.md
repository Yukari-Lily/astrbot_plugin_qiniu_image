# astrbot_plugin_qiniu_image

七牛 Modelink 绘图 / 改图插件，适用于 AstrBot。当前版本 **2.3.0**。关键词绘图继续沿用 1.3.0 的基础路径。

## 使用流程

主聊天模型调用 `prepare_drawing(brief, caption)`，插件立即返回 `accepted` 和任务编号，在后台解析图片、规划并自动发图。**无需再调用 `draw_image`，也无需等待或审核摘要。** 旧的 `draw_image` 入口仅用于兼容，重复提交已受理任务不会再次出图。

`brief` 只包含用户明确的主体、动作、构图、文字、硬性要求及必要指代。例如“你的自拍”应补充 Bot 的明确人设；已有 IP 角色应提供名称和作品，不把聊天模型凭记忆补充的服装、发色或道具混入用户要求。已有角色的外观由后台按需核实，原创主体完整保留用户设定。

`caption` 是主聊天模型按当前人格写的一句短回复，60字以内，简单说画谁即可。插件在完整提示词就绪后代发，再发送图片；没有提供时使用“按你的要求画一张。”。绘图过程中不播报搜索、核对、重试等过程话术。主模型处理完所有请求后只输出内部标记 `QINIU_DRAWING_DONE`，由插件隐藏。

连续新增请求分别受理，不必等待上一份。相同消息内重复调用相同委托和选项会返回原编号；不同消息、不同委托和不同 Bot 独立处理。`accepted` 只表示受理，不表示图片已生成。

## 后台预算与方案快照

图片解析、规划、搜索、图片核对和提示词整合共用 **45秒前置预算**。图片解析单次最多10秒；普通提示词整合最多20秒，且不能超过剩余总预算。实际七牛图片生成及消息发送不计入前置预算。

1. 受理时先保存用户委托和可沿用的基稿，分配稳定任务编号。
2. 搜索前记录主体与模型原有认识，但不把待确认认识写入可出图快照。
3. 每个主体完成文字核实后，通过内部 `save_subject_assessment` 保存特征；图片核对成功会自动更新快照。其他角色尚在搜索时，已核实内容也已保留。
4. 资料足够时立即返回完整方案并出图，不必用完预算。已保存的主体判断不必在最终 JSON 中重复填写。
5. 超时或规划返回无效结果时，取消剩余工作，用最新快照本地整合并提交图片生成。**不再启动一次收尾模型，也不从头重试搜索。**

快照按“用户要求 + 已核实特征”重建。存疑的搜索前认识和未经判断的网页内容不会直接写入确定特征；未完成主体标为 `unverified`，保留名称及绘画意图。快照只保存最新一份，`snapshot_revision` 表示更新次数。正常方案仍由规划模型设计构图和动作；快照兜底会减少未经核实的外观细节，成图准确度仍取决于资料及模型能力。

预算耗尽或整合模型不可用时，在本地保留完整方案并追加已选画风核心片段和基础质量要求。若规划尚未选出画风，文生图快照默认净色动画壁纸；已有画风、配置禁用及用户明确的画风要求优先。

## 简单请求的快路径

| 请求 | 行为 |
| --- | --- |
| 原创角色、原创场景或无需外部知识的请求，`research_mode="skip"` | 不提供搜索工具，调用一次规划模型后本地整合 |
| 有输入图、`image_mode="edit"` 且未要求换风格 | 直接按委托改图，不调用规划或整合模型 |
| 有输入图、`image_mode="reference"` | 通过视觉规划参考创作，不联网核对 |
| `research_mode="auto"` | 使用本次请求启用的搜索工具按需核实；没有搜索工具时直接调用规划模型 |

`research_mode` 默认 `auto`，主聊天模型根据用户意图选择 `skip`，不靠角色名称关键词强行分类。需要已有 IP 外观知识时应保留 `auto`。

## 核实角色与来源

文字特征与搜索前认识相符时直接采用；没有先验认识时用可靠搜索资料补足。只有文字冲突时调用 `compare_subject_reference` 下载图片，至少两方一致才采用共同特征。第一轮无共识时重新搜索、获取新图片再核对，最多两轮，也受剩余预算限制。

内部保存工具校验本次真实来源，不能使用其他主体的网址或虚构来源；冲突未完成核对、搜索失败却声称已核实的记录不能进入确定特征。已核对特征若被最终方案改写为同义表达，会补入核对原文，避免仅因未逐字复述而重新规划。语义一致性仍由模型判断。

搜索只继承受理请求实际启用的 AstrBot 内置工具：Baidu、Tavily、Bocha、Brave、Firecrawl、Exa、AnySearch 及对应页面读取工具。不新增搜索 Key，不自动启用被禁用的工具，自定义 MCP 搜索暂不自动转交。网页和图片下载仅允许公开 HTTP(S) 地址，并限制 DNS、重定向、大小与耗时。

## 画风与模型分工

| 模型 | 职责 |
| --- | --- |
| 主聊天模型 | 解释用户意图，提交明确要求、画风原话、短回复及研究模式 |
| 绘图规划模型 | 独立上下文内按需搜索、核对并保存特征，选择风格，完成构图 |
| 提示词模型 | 在剩余预算内选择相容的既有风格/质量片段，不改写方案 |
| 图片模型 | 执行完整提示词，生成或修改图片 |

`planning_provider_id` 可指定独立规划 Provider；留空复用当前聊天 Provider，但不带入完整聊天历史。`rewrite_provider_ids` 用于普通提示词整合、关键词优化和上游审核拒绝后的安全改写，不负责图片核对。

`style_request` 仅填写用户明确说出的画风原话；未要求时留空，不能把角色原作的3D/厚涂媒介当成用户要求。修改内容时留空沿用原风格，换风格时填新要求，恢复自动选择填 `auto`。

保留13个内置风格及 `style_mode`（`auto` / `explicit_only` / `disabled`）、`style_strength` 设置。规划模型先选风格再设计画面；单人/单主体偏好错位矩形、诗意窗口等，多人/多主体偏好净色动画壁纸，明确要求优先。整合器不能改选风格或删掉核心视觉片段；快照兜底采用最小核心片段。

## 图片、修改与取消

发送或引用图片时，使用第一张可用图片。`reference` 表示参考创作，`edit` 表示局部修改且其余保留原图；`auto` 由规划模型判断，规划失败时保守使用 `edit`。原图会随任务保存，有图时绝不搜索或做三方核对。图片解析超时或明确指定改图却没有可用图片时报告失败，不降级为文生图。

修改上一张作品用 `prepare_drawing(brief="只改指定部分", use_last=true)`，自动沿用同一会话、同一用户最近执行的完整提示词。修改指定任务可用 `base_plan_id`；新任务受理后，尚未开始生成图片的旧任务会停止并标为 `superseded`。已经进入图片生成的任务需要等完成后再修改。

用户明确取消时调用 `cancel_drawing(plan_id)`，可取消规划或整合中的后台任务；任务已经进入图片生成时不能通过此入口撤回。插件卸载会取消在途后台任务。

## 查询、日志与缓存

`get_drawing_plan(plan_id)` 返回当前状态、快照版本、摘要、搜索次数及主体判断；`full=true` 才返回完整提示词和实际证据。`get_last_image_prompt(full=true)` 查看最近实际提交给图片模型的提示词。无需为等待出图而轮询工具。

日志可按 `plan_id` 和 `umo` 追踪 `accepted`、`snapshot`（调试级别）、`snapshot used`（提前停止规划）、`prompt ready`、`generation request` 和 `delivered`。`delivery_failed` 表示消息平台未接受图片发送。若发生上游安全改写，方案全文和最近提示词同步更新，`style_selection` 仍代表最初整合的选择。

方案与证据缓存最多100份、30分钟，估算上限128 MiB；规划、整合和生成中的任务不会被过期或容量回收移除。最近执行提示词保留最多100个会话/用户记录。缓存仅在内存中，重启清空；历史提示词不包含成图像素，精确改图请引用该图片。

关键词 `triggers` 的匹配、去重、同步出图和提示词优化保持原路径，不经过新增后台规划。Modelink API、PNG 输出、图片生成并发、网络重试及上游实际审核拒绝后的安全回退保持原有行为。

## 验证

```shell
python -m unittest discover -s tests -v
```

离线测试模拟 AstrBot Provider、搜索工具、图片下载、图片生成和消息发送，覆盖即时受理、统一预算、逐主体快照、来源校验、取消、连续请求、图生图快路径、缓存、用户隔离及关键词路径。实际模型的资料判断与成图效果仍需在运行中的 AstrBot 联调。
