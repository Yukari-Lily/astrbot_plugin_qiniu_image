# astrbot_plugin_qiniu_image

七牛 Modelink 原厂 `bypass` 协议绘图 / 改图插件，适用于 AstrBot。

## 使用

直接用自然语言请求绘图或改图，例如：

```text
帮我画一只穿宇航服的柴犬
把这张图改成夜景
```

插件默认通过 `draw_image` 工具触发，也可以在 `triggers` 配置中添加确定性触发词。改图时可直接发送图片或引用图片消息。

## 内置风格

插件会在同一次提示词改写中，根据用户需求选择一个合适的内置风格或借用其部分特征；只有风格与需求明显冲突时才不选择。用户明确指定的内容和风格始终优先，不会为了套模板而替换角色、品牌、文案、构图或配色。改图时只有用户明确要求风格化，才会改变原图画风。

当前内置风格：

- 文艺电商联动物料
- 俄国构成主义
- 错位矩形·强故障版
- 错位矩形·诗意窗口版
- 混合媒介·照片与素描
- 半调双色雕刻
- 半调杂志
- 波普与水墨喷溅
- 克莱因秩序
- 米白红色电路图
- Y2K 与波普艺术
- 赛璐璐平涂与思维爆发

自动选择会优先考虑：两种错位矩形风格、半调杂志、波普与水墨喷溅、米白红色电路图、赛璐璐平涂与思维爆发。

插件还注册了 `list_image_styles` 查询工具。普通聊天中用户询问“你会哪些画风”或要求推荐风格时，聊天模型可以直接读取与实际预设同源的风格目录，无需维护一份容易过期的独立 Skill。

改写时会同时参考用户原话和聊天模型生成的工具参数，并以用户原话为准。`anime style`、`masterpiece`、`highly detailed` 等泛化质量词不会再被误判为用户已经指定完整画风。默认审美底线（干净、通透、有明确视觉层级的二次元表现，抑制浑浊棕黑、油腻厚涂、无目的颗粒和背景过载等脏乱效果）只会在没有使用内置风格时注入；选用了内置风格时以风格规则为准，用户明确要求的媒介仍然优先。

style_mode 控制选用方式：auto 智能选择、explicit_only 仅明确点名时选择、disabled 不注入内置风格库。style_strength 控制风格表现强度。内置风格依赖提示词改写，因此 rewrite_scope=never 时不会生效。

## 安全转译

首次出图前不进行风险词检测，也不注入安全转译规则。只有图片平台实际返回安全审核拒绝后，插件才会按 `safety_rewrite_attempts` 生成安全替代提示词并继续尝试，默认最多 5 次。安全程度分五级递进：先通过同义替换、隐晦措辞等措辞级调整尝试保留原画面（不改动服装、场景、姿势与构图），前两级还会优先使用动画角色插画、角色立绘、轻小说封面、动画剧照等二次元插画语境措辞，并避免私密场景、暴露服装与挑逗姿势叠加；仍被拒绝后才依次增加遮盖并减弱暗示、改为完整家居服或时装、端庄日常服装与中性场景，最后才是全年龄普通角色插画；不会第一次就直接套用最保守版本。它不会原样生成裸露、性行为或未成年人性化内容。`moderation` 默认 `low`（放宽审核阈值，仅对中等敏感内容有效），如遇上游不支持该参数或需要更严审核，可设为 `auto` 恢复上游默认。

`rewrite_provider_id` 可将提示词改写固定到单独的 AstrBot Provider；留空则跟随当前会话。主模型失败时，会按 `rewrite_fallback_provider_ids` 的顺序继续尝试备用模型，每个模型最多调用 `rewrite_attempts_per_provider` 次。全部改写模型均失败时，本次绘图会终止，不会把未经优化的提示词直接发给图片模型。

图片请求遇到网络异常、限流、5xx 或异常响应时，由 `retries` 控制直接重试；鉴权、权限和参数错误不会进行无意义重试。独立改写模型适合用于提升提示词遵循、中文理解和视觉理解能力，不应用于规避安全规则。

## 配置

配置项及默认值见 `_conf_schema.json`。至少需要填写 `api_key`；默认使用后台出图模式，完成后会主动发送图片。
