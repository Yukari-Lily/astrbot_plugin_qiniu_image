# astrbot_plugin_qiniu_image

七牛 Modelink 绘图 / 改图插件，适用于 AstrBot。当前版本 **2.2.0**。绘图与关键词基础仍来自 **1.3.0（`5020e13`）**，不使用之后的外观定字段、角色缓存和复杂人物任务结构。

## 模型分工

| 模型 | 职责 |
| --- | --- |
| 主聊天模型 | 解释用户意图、会话指代和必要人设，给出硬性要求与创作自由度，检查摘要并决定出图 |
| 绘图规划模型 | 在独立上下文里搜索、核对特征、设计动作与构图，准备完整方案 |
| 提示词模型 | 只选择相容的既有内置风格与全局兜底片段，完整方案逐字保留 |
| 图片模型 | 执行已确认方案并生成图片 |

主聊天模型不需要承担整套搜索/核对流程，也不默认接收长提示词、网页内容或图片核对过程。规划模型只接收本次委托、按需读取的历史提示词，以及用户输入图片，不读取完整聊天历史。

## 使用流程与主模型控制

1. 主模型调用 `prepare_drawing(brief)`。委托应写清意图、必要人设/指代、硬性要求和允许自由设计的部分。例如“你的自拍”必须先说明“你”的形象，不能让规划模型猜群聊上下文。
2. 插件返回方案编号、简短摘要、搜索次数及各主体核对状态，尚不出图。
3. 主模型检查摘要。不满意时调用 `prepare_drawing(brief="具体修改要求", base_plan_id="原编号")`，新方案准备成功后旧的待审稿失效；符合委托后调用 `draw_image(plan_id)`。
4. 插件整合风格并保存完整提示词，返回 `accepted` 与编号，后台生成并发图。同一方案不能重复执行。

审核是主聊天模型的内部步骤，无需额外向用户索取批准。规划模型只获得联网和内部核对工具，没有出图、发送消息或修改文件的工具。方案编号保证出图使用已准备的那一稿，不能直接传自由提示词绕过规划。

主模型需要核查细节时，调用 `get_drawing_plan(plan_id, full=true)` 获取完整方案和实际搜索/核对依据；默认只给摘要。主模型对委托目标与执行决定有控制权，摘要是否充分、规划判断是否正确仍依赖模型能力。

## 规划模型的文生图流程

- 逐个主体判断：是否理解用户在说什么；是否有把握描述特征。任一没把握就先消歧、再搜特征，保留搜索前的原有认识。
- 文字特征一致就采用，不取图；无先验知识时，以明确可靠的搜索资料补足，不编造自己的认识。原创主体以委托设定为准。
- 只有文字特征冲突时，内部调用 `compare_subject_reference` 下载图片。图片是高优先级证据，只采用至少两方一致的共同特征。
- 第一轮无共识时重新搜索并取新图片，再核对一次；第二轮仍失败就省略不可靠特征，保留名称、动作构图，让图片模型发挥。多主体分别处理。

这些细节不注入主聊天模型。插件记录真实搜索结果，核对只能使用本次结果中的来源；两次核对之间必须再次执行搜索，第二轮不重复比较相同图片字节，未完成必要核对的方案不能进入待审状态。下载只允许公开 HTTP(S) 地址，并限制 DNS、重定向、大小与耗时。

搜索仅继承当前聊天请求实际启用的 AstrBot 内置联网工具（Baidu、Tavily、Bocha、Brave、Firecrawl、Exa、AnySearch 及对应页面读取工具），不新增搜索 Key，也不自动开启被禁用的工具。自定义 MCP 搜索工具暂不自动转交。没有联网工具时在摘要中标明限制，要求规划模型省略无法可靠描述的特征。

联网判断、文字是否一致及图片语义核对仍由规划模型完成。取图或视觉失败同样遵循两轮兜底；规划整体超时或返回无效方案时不出图，主模型可重新准备。

## 图生图

直接发送或引用图片，沿用 1.3.0 的第一张可用图片解析。

- `image_mode="reference"`：以用户图片为主体依据，按委托及相容内置风格创作。仅说“参考这张图”属于这一模式。
- `image_mode="edit"`：仅局部修改，其余保持原图，不自动改变画风。
- `image_mode="auto"`：默认，由规划模型根据委托判断。

有用户图片时，规划模型通过视觉理解图片，**不获得任何搜索或三方核对工具**。提示词模型不看图。方案保留本次用户图片引用，后续确认出图不会换成另一条消息的新附件；修改同一待审稿时可以沿用原输入图。

## 后续修改与缓存

普通修改可直接调用 `prepare_drawing(brief="只改指定部分", use_last=true)`，插件将同一会话、同一用户最近的完整提示词直接交给规划模型。主聊天模型无需先读取或复述全文。

`get_last_image_prompt()` 默认仅返回摘要和编号；需要检查实际执行文本时使用 `full=true`。完整画风与全局兜底段沿用时不重复叠加，换风格时规划模型应移除旧风格段。

方案与证据缓存最多 100 份、30 分钟，估算体积上限 128 MiB；最近执行提示词最多保留 100 个会话/用户记录。缓存均在内存，重启后清空。历史提示词用于延续内容，不保存成图像素；精确修改某张成图时可引用该图片消息。

`accepted` 不代表已生成成功。审核拒绝后的安全替代提示词会更新方案全文与最近记录，并标记原摘要可能已不准确，主模型可按需查看实际文本。

## 配置与保留行为

新增 **绘图规划模型 `planning_provider_id`**，可选择独立的 Provider，需要工具调用与视觉能力。留空时复用当前聊天 Provider，仍运行在独立上下文，不带入聊天历史。

`rewrite_provider_ids` 继续用于提示词整合、关键词优化及审核后的安全改写，不负责规划或图片核对。建议为规划模型选择有足够推理、工具调用和视觉能力的模型，整合模型只需可靠遵循文本与 JSON 指令。

其余配置和 13 个内置风格保持原有体系。`style_mode` 为 `auto` 时自动选相容风格，`explicit_only` 只在点名时使用，`disabled` 关闭；后两项也适用于参考图。`style_strength` 控制片段使用程度。

关键词 `triggers` 的匹配、去重、同步出图和提示词优化保持 1.3.0 路径，绕过新增规划与审核入口。Modelink API、PNG 输出、并发、网络重试和上游实际审核拒绝后的五级安全回退保持原有行为。

## 验证

```shell
python -m unittest discover -s tests -v
```

离线测试模拟 AstrBot Provider、工具执行、图片下载和出图接口，覆盖独立规划、审核入口、真实搜索记录、两轮核对、图生图隔离、按需全文、缓存继承、用户隔离、重复出图与关键词路径。实际模型的规划质量、摘要忠实度与成图效果需在 AstrBot 中联调。
