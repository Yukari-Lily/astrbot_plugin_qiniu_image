# astrbot_plugin_qiniu_image

七牛 Modelink 绘图 / 改图与 Grok 视频插件，适用于 AstrBot。当前版本 **2.1.0**。

聊天出图恢复 1.3 的提示词逻辑：主聊天模型形成完整画面方案，优化器整理并融合适用风格与质量要求，图片模型执行。关键词保持原文直出，新版图片处理、重试和续画隔离继续保留。

## 安装与升级

在 AstrBot 插件市场安装，或将本目录放进 `data/plugins/`。生图填写 `api_key`，并确保当前会话或配置的优化模型可用。仅生视频时只需配置 grok2api，无需七牛密钥。

**更新后重新加载插件，刷新绘图和视频工具说明。** 原有绘图工具参数与配置名称不变，无需重新选择图像模型。旧 context 参数与 AstrBot 内部参数冲突，仍使用 subject_info；绘图工具不接受独立 style 参数，明确画风写入方案。

## 配置

| 配置项 | 说明 |
| --- | --- |
| `api_key` | 七牛 Modelink 密钥 |
| `model` | 同时支持文生图与改图的图像模型，默认 openai/gpt-image-2 |
| `rewrite_provider_ids` | 优化与安全改写模型，按顺序回退；留空跟随当前会话 |
| `quality` / `size` | 画质与尺寸，auto 由图片模型决定 |
| `moderation` | 上游审核设置，支持 low / auto |
| `concurrency` | 图片请求最大并发数，超出后排队 |
| `enable_styles` | 是否允许优化器自动匹配内置风格 |
| `style_strength` | 优化时的风格融合强度：subtle / normal / strong |
| `triggers` | 可选原文直出触发词；不要填写 Bot 唤醒词 |
| `grok2api_base_url` | 自部署服务地址，例如 `http://127.0.0.1:8000/v1`，可省略 `/v1`；留空禁用 Grok |
| `grok2api_api_key` | grok2api 密钥；服务关闭鉴权时可留空 |
| `grok2api_concurrency` | Grok 图片与视频任务共用的并发上限，默认 2 |
| `grok2api_video_timeout` | 视频创建与轮询的总超时，默认 600 秒，不含排队和下载 |

## Grok 视频

使用自部署 [grok2api](https://github.com/chenyme/grok2api) 的 `grok-imagine-video`。先填写服务地址和密钥，并在上游启用该模型。地址必须能从 AstrBot 访问；如果分别部署在容器内，请填写对应的容器服务名或宿主机地址。

- 指令：`/生视频 纸飞机飞过城市，镜头跟随`，默认 8 秒、16:9、720p。
- 聊天：直接要求生成视频，主模型调用 `generate_video(prompt, duration=8, aspect_ratio="16:9", resolution="720p")`。支持 1～15 秒，比例 1:1、2:3、3:2、9:16、16:9，分辨率 480p 或 720p。
- 当前消息或引用消息中的第一张图片自动作为首帧；没有图片时文生视频。有图片但读取失败时会报错，不会静默改为文生视频。

视频提示词由主模型整理后直接提交，不经过生图优化器和画风模板。插件后台创建任务，按 `request_id` 轮询 `pending/done/failed`，完成后下载 MP4 并发送，临时文件随后清理。下载限制 200 MiB、180 秒。仅查询任务会重试，创建任务不会自动重发；插件卸载时取消本地任务，已创建的上游任务可能仍在执行。

## Grok 生图兜底

使用 `grok-imagine-image-2.0`，文生图和带原图编辑均支持。首次出图仍使用配置的七牛模型；遇到明确审核拒绝后，顺序如下：

1. 原模型使用第一层安全改写词。
2. 仍失败时，Grok 使用**初始提示词**，即首次提交给原模型的完整提示词。
3. Grok 失败后，使用第一层安全改写词再生成一次；复用已有第一层改写，若此前没得到可用改写则重新请求第一层改写。
4. Grok 仍失败或改写不可用，再继续原模型第 2～5 层安全改写。

未配置 grok2api 时保留原五层逻辑。Grok 成功即结束，不再请求后续层；成功记录保存该次实际提示词。兜底始终保留输入图和图片约束，不把改图变成文生图。七牛的 `size` 在 Grok 文生图时映射为宽高比，Grok 画质与分辨率使用上游默认值。

## 聊天出图

主模型根据用户要求、已有会话和人设形成完整绘图方案。用户留出创作空间时，可合理设计姿势、服装、镜头、构图、光影与配色；用户明确限制优先，局部编辑不扩大范围。常见角色直接补全可靠身份，只有无法可靠识别时先搜索、阅读，再调用绘图工具。

| 请求 | 处理方式 |
| --- | --- |
| “画千束” | 补全可靠身份，形成协调的画面方案，可由优化器匹配画风 |
| “看你的自拍” | 结合 Bot 已有外貌与自拍语境设计画面，不编造身份 |
| “穿雨衣的千束，水彩” | 保留角色、雨衣和水彩，围绕明确要求组织画面 |
| “把上一张帽子改蓝” | 提供本轮改动并设置 use_last_image=true，继承其余内容 |

优化器以主模型方案为权威创作来源，原话仅用于核对明确限制；不因原话短就删除主模型的授权设计，也不重新规划画面。输出是一段已经融合视觉要求的完整执行提示词。subject_info 仅补充必要事实或指代信息，不传完整群聊或人格规则。

工具立即受理，后台完成优化与出图。同一请求调用一次，受理后只发一条简短确认，不持续发送进度；图片由插件自动发送。

## 风格

预设以 1.3 为基础，净色动画壁纸额外降为低优先、仅限多人，并排在目录末尾。优化器理解同一份目录的名称、别名及适用范围，最多选择一个风格：

- 明确点名的内置风格优先；外部具体画风或已有完整视觉方案不强套模板。
- 缺少具体画风时选择相容项，多个适合时优先目录标记的“默认优先”项。
- 用户不要内置风格、关闭风格或所有候选不相容时可以留空；局部改图默认保留原图。
- 续画默认继承上一稿风格；本轮明确换风格时按新要求处理。
- 净色仅限明确至少两名独立人物；单人、无人、人数不明不能使用，也不能为选净色添加人物。选择净色必须返回人数与输入中的多人依据，校验失败要求换风格；继承净色时同样校验。

风格是视觉参考，只将适用的色彩、线条、材质与构图融入执行稿，可以舍弃不适用的倒立、悬浮、强透视和轮廓融合。既定姿态、构图与配色优先，装饰不应破坏人体结构可读性。

subtle 借用少量特征，normal 使用核心视觉语言并删除冲突细节，strong 充分使用相容的构图、色彩和材质。全局质量要求同样在优化阶段融合，避免为清洁度丢失必要结构、体积与光影。**聊天提交时不再机械追加整段预设和质量规则。** 风格查询工具可用于介绍或创作参考，出图无需先查询。

## 图片与续画

优先读取当前消息图片，其次引用消息图片。keep_layout=true 表示局部改图，除明确修改外保持原图；false 表示以图中主体为参考重建场景、姿势和构图。图片只交给图片模型，文字优化器不看图。确认有图但不可读时报告失败，不改走文生图。

use_last_image=true 在受理时取得当前会话、当前用户上一份成功执行稿的快照，由优化器执行本轮修改。主模型无需先查询或转抄底稿，没有记录时明确报错。

`get_last_image_prompt` 返回成功出图时**实际提交的完整提示词**、风格、融合状态和图片用途。记录不含图片像素，精确修改请引用原图。记录按会话和用户隔离，最多 100 条，仅内存保存，重启清空；失败不覆盖上一稿。

## 关键词原文直出

以 triggers 中的词开头的消息绕过主模型和正常优化，去掉触发词后的原文作为方案，只追加图片约束与全局质量段，不自动选择内置风格。该入口保持原有行为，适合直接提供完整提示词。

关键词等待并返回图片，按会话来源和消息 ID 去重。两种入口共用图片生成和错误处理，卸载时统一取消在途任务。

## 失败处理与诊断

优化器返回 JSON 完整执行稿和准确风格 ID。空风格需声明有效原因：保留原图、保留无风格上一稿、外部画风、不使用风格、保留具体方案或候选不相容；不再要求逐字引用原话。格式错误、拒答或非法 ID 会反馈给模型修正。

正常优化每次最多 120 秒，安全改写 45 秒；每轮按配置顺序尝试模型，失败先切备用，每模型最多三次。全部失败停止，不使用未经优化的聊天方案降级生成。

只有图片平台明确审核拒绝才进入安全改写；第一层失败后按上文尝试 Grok 兜底，未配置或 Grok 失败时保留原模型后续层的流程。聊天改写接收完整执行稿，保留安全的角色与视觉设计，重试不重新套模板；关键词仍改写原文并追加既有质量段。首次生成的鉴权、限流、网络和无效图片错误分别处理，不触发安全改写。

INFO 记录优化正文、风格、留空原因、融合状态及实际图像模型、质量与尺寸。DEBUG 包含完整提交提示词，成功后也可通过查询工具读取，便于比较提示词和成图效果。

编辑接口继续优先 JSON，仅在明确要求 multipart 时回退上传。输入本地下载或解码支持 PNG、JPEG、WebP、GIF，限制 40 MB；输出支持 PNG、JPEG、WebP，限制 80 MiB。输入 URL 直接交给上游时由上游读取。

## 验证

离线测试：`python -m unittest discover -s tests -v`。测试使用 mock 验证流程，不代表实际画质改善。真实成图需在 AstrBot 中固定请求、模型、质量与尺寸，对 1.3 和修改版各生成至少三张，记录执行稿并比较人体连续性、构图与风格融合。
