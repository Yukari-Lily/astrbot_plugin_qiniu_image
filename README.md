# astrbot_plugin_qiniu_image

七牛 Modelink 原厂 `bypass` 协议绘图 / 改图插件，适用于 AstrBot。

## 使用

直接用自然语言请求绘图或改图，例如：

```text
帮我画一只穿宇航服的柴犬
把这张图改成夜景
```

插件默认通过 `draw_image` 工具触发，由主聊天模型理解完整上下文和 Bot 人设；也可通过 `triggers` 配置确定性的直接出图触发词。改图时可直接发送图片或引用图片消息。

## 内置风格

插件会在同一次提示词改写中，根据用户需求选择一个合适的内置风格或借用其部分特征；只有风格与需求明显冲突时才不选择。用户明确指定的内容和风格始终优先，不会为了套模板而替换角色、品牌、文案、构图或配色。改图时只有用户明确要求风格化，才会改变原图画风。

当前内置风格：

- 净色动画壁纸
- 文艺电商联动物料
- 俄国构成主义
- 错位矩形·强故障版
- 错位矩形·诗意窗口版
- 混合媒介·照片与素描
- 半调双色雕刻
- 半调杂志
- 波普与水墨喷溅
- 克莱因秩序
- 米白红色电路图
- Y2K 与波普艺术
- 赛璐璐平涂与思维爆发

自动选择会优先考虑：净色动画壁纸、两种错位矩形风格、半调杂志、波普与水墨喷溅、米白红色电路图、赛璐璐平涂与思维爆发。

插件还注册了 `list_image_styles` 查询工具。普通聊天中用户询问“你会哪些画风”或要求推荐风格时，聊天模型可以直接读取与实际预设同源的风格目录，无需维护一份容易过期的独立 Skill。

主聊天模型结合人设、完整群聊上下文和必要考据完成创作，再提交完整方案与人物名单。优化模型只写动作、表情、姿态、构图、光照、画风与文字，**不接触人物外观**；发型、发色、瞳色、服装、配饰由插件从外观记录里逐字写进最终提示词。这条分工是刻意设计的：外观一旦交给优化模型转述，就没有任何一环被要求保留它。多人场景逐人描述并校验人物数量、标识与顺序。关键词直出仍把触发词后的文本作为完整方案。

调用 `draw_image` 时，聊天模型应直接识别常见作品、角色和昵称，并补全关键官方信息；不确定某个角色长什么样时，先用 Web 搜索找到它的资料页，把网址交给 `prepare_character_reference`，再调用绘图工具。两步必须串行。这个限制通过工具说明引导聊天模型执行，插件本身无法拦截 AstrBot 对其他工具的调度。

插件在聊天请求前注入一段约 400 字的作图约定、风格名称与别名，以及当前用户近期作品的标识，不替换 Bot 人设或复制整段历史。例如“错位千束”会先按内置风格理解，再决定是否需要搜索人物。风格目录工具只输出标题。

每次绘图后台受理，完成后自动发送图片。`get_last_image_prompt(generation_id="latest")` 可读取当前会话当前用户近期作品的完整执行稿、所用风格与人物名单。作品原文只保留在内存中，按“会话＋发起用户”隔离，每人最多 5 条，插件重启后不恢复。

优化时 `anime style`、`masterpiece`、`highly detailed` 等泛化质量词不会被误判为完整画风。内置全局审美规则会在所有普通优化中注入，进一步约束动画画面使用大色块、低视觉频率、受控边缘密度、清晰边缘层级、少量内部轮廓线和大块阴影，并抑制碎阴影、微纹理、微对比和无必要高光。

内置风格名称只用于路由和日志，不会发送给图片模型。插件会删除内部风格标记、中文风格名及别名，只保留展开后的构图、色彩、线条和材质描述。日系动漫、漫画及游戏角色默认使用官方日文作品名、角色名和画内字样，不使用中文译名作为海报装饰文字。

风格优先级依次为：用户本轮明确指定的画风；目标作品需要保留的原有画风；主模型自行选择的画风。图片不作为画风依据。`auto` 模式下，主模型先从相容的内置高偏好风格中选一个，优化器也按此规则核对；自行补上的普通动画主视觉、电影感或 3D 渲染不视为用户指定画风，人物原作品为 3D 也不锁定本次媒介。用户指定外部画风、原风格复刻或局部编辑保留原貌时仍优先遵守。旧工具调用和直接触发词没有结构化来源信息，继续尊重完整提示词中的具体画风。`explicit_only` 仅响应用户点名，`disabled` 关闭内置风格路由；`style_strength` 控制表现强度。

优化器启用风格路由时必须返回一个有效的内部风格选择标记，缺失或无效时按原有优化 Provider 重试、回退。插件会尽量让每一张图都套上一个内置风格：风格路由启用时同时下发"不要输出 `STYLE_PRESET:none`"的约束，只有用户明确要求了其他具体画风、纯写实摄影、忠实复刻原画风、明确要求不要风格化，或全部候选都与画面硬性要求冲突时才允许不选；优化器仍然选了 `none` 时补一次定向重试，重试仍选 `none` 则接受，不会为了套风格而阻断出图。线条执行约束同时发送给优化器和绘图接口，减少草稿复线、乱排线、密集碎发及装饰线；错位、思维爆发和电路等预设也减少线网及碎片。人物标志物、明确要求的线性艺术和局部编辑保留项优先，不一律删除必要细节。

提示词优化与全局审美规则为固定流程。**从网上取得的角色参考图永远不会进入绘图接口**，它只用来产出一份文字外观记录；只有用户原消息自带的 `input:N` 图片才会作为图片输入传给七牛。原消息无图时最终走纯文字生成。优化模型只接收本次方案，不接收外观记录。

## 人物名单与外观记录

`draw_image(prompt, characters=None)`：`prompt` 是主聊天模型形成的完整方案（动作、表情、场景、构图、光照、画风、文字），`characters` 是画面中的具名人物。

| 字段 | 说明 |
| --- | --- |
| `name` | 准确人物名称，必填 |
| `work` | 所属作品、系列或身份，用于区分同名角色 |
| `version` | 具体形象版本，例如某代立绘、某种服装 |
| `position` | 从观看者视角描述的位置；多人时必须逐人填写 |
| `id` | 人物标识，可省略；用于多人场景下逐人对应 |

```json
{
  "prompt": "夏日海滩的黄昏，五个人并排站在浅水里挥手，逆光，动画电影质感",
  "characters": [
    {"name": "中川花音", "work": "只有神知道的世界", "version": "夏季制服", "position": "从左数第二位"},
    {"name": "桂木桂马", "work": "只有神知道的世界", "position": "从左数第三位"}
  ]
}
```

插件按 `name` / `work` / `version` 自动从外观缓存里取记录，**模型不需要传递任何句柄**。取到的记录由插件逐字写进提示词，紧贴在该人物的标题行下方：

```text
人物 p1（中川花音 / 只有神知道的世界 / 夏季制服；从左数第二位）：挥手微笑，衣摆被风吹起
外观锚点（稳定特征，与文字要求冲突时以此为准）：剪影：…；发型：…；发色：…；瞳色：…
```

缓存按 `sha1(作品|名字|版本)` 索引，同时用准确名做别名键，避免“准备时叫小秦、画时叫秦某”导致漏接。TTL 6 小时，最多 200 条，纯文本、进程内、不落盘。

## 冷门角色的外观查询

`prepare_character_reference(name, source_urls, work="", version="")`。

搜索沿用 AstrBot 已有的联网能力：主聊天模型先用它的搜索工具找到该角色的资料页或图片直链，再把网址填进 `source_urls`（1～4 个）调用本工具。**插件不需要任何搜索密钥，也不新增搜索配置。**

插件下载来源页，提取正文、图注、懒加载图片与封面，最多取 6 张候选图（总预算 40 秒），然后把页面正文和图注连同图片一起交给一次视觉调用，要求它：

- 选出一张并给出 `canonical_name` 与 `identity_basis`（**身份依据与外观彻底分开记录**）；
- 按固定键位逐字段填出可见外观，只写图里看得见的像素，不补充先验印象，不记录动作、表情、姿势、镜头、背景、光照或画风；
- 真的没有该特征就留空，左右不对称必须写明哪一侧；
- 身份依据不足或候选图是别的角色／网页 logo 时返回 `uncertain`，插件不取平均、不猜。

插件侧有三道确定性防线：定键 schema 挡住自造字段与超长小作文；覆盖度校验按严重度分档——**必需字段**缺失、占位（`未知`/`无`/`n/a` 等）、过短、含 `?`，或同一描述铺满 4 个以上字段，属致命问题，整份记录不可用；**可选字段**上的同类瑕疵只让那一项不渲染，不影响整份记录，也不触发重试；只有致命问题才带着**问题清单**定向重试一次，仍不合格就返回 `unavailable` 且**不出图**，绝不伪造记录。分档的理由：可选字段写个占位词就让整个角色退回纯文字出图，正是这套记录要修的毛病。

网页取图只访问公开 HTTP(S) 地址，检查 DNS 解析结果和每一次重定向，拒绝内网、凭据 URL、异常端口、过大内容与不支持的格式；单个候选读取最多 10 秒，单个来源最多 10 秒。不会绕过登录或反爬。

## 多人出图

多人图逐人描述并逐人附着外观锚点，属性不会串味。人物数量、标识与顺序必须与名单严格一致，优化模型输出错位或漏人时会重试；彻底给不出逐人结构时退化为整体场景描述，人物标题与外观锚点照旧由插件写入，锁不受影响。

人物外观是否可靠**不再靠出图后的视觉复查**。抽取阶段的覆盖度校验已经确定性拦住了偷懒与编造，出图后再用视觉模型抽查既贵又无法真正修正，因此这条路径已移除。

## 安全转译

首次出图前不进行风险词检测，也不注入安全转译规则。只有图片平台实际返回安全审核拒绝后，插件才会生成安全替代提示词并继续尝试，固定最多 5 级。安全程度逐级递进：先通过同义替换、隐晦措辞等措辞级调整尝试保留原画面（不改动服装、场景、姿势与构图），前两级还会优先使用动画角色插画、角色立绘、轻小说封面、动画剧照等二次元插画语境措辞，并避免私密场景、暴露服装与挑逗姿势叠加；仍被拒绝后才依次增加遮盖并减弱暗示、改为完整家居服或时装、端庄日常服装与中性场景，最后才是全年龄普通角色插画。某一级的安全改写模型若拒绝回答、返回空内容或无效结果，插件不会立即终止，而会继续尝试更保守的下一级；图片平台再次拒绝时同样推进一级。全部级别都无法产出可用图片后才失败。它不会原样生成裸露、性行为或未成年人性化内容。`moderation` 默认 `low`（放宽审核阈值，仅对中等敏感内容有效），如遇上游不支持该参数或需要更严审核，可设为 `auto` 恢复上游默认。

`rewrite_provider_ids` 使用 AstrBot 的有序模型选择器：第一项是主优化模型，后续项按顺序作为回退模型；留空则跟随当前会话。每个模型固定最多调用 3 次。全部优化模型均失败时，本次绘图会终止，不会把未经优化的方案直接发给图片模型。该选择器在 AstrBot v4.28.0 可用，目前属于 AstrBot 内部配置控件，未来大版本若调整内部接口可能需要随之适配。

图片请求遇到网络异常、限流、5xx 或异常响应时固定最多尝试 4 次，单次请求总超时为 480 秒；鉴权、权限和参数错误不会进行无意义重试。纯文字绘图可以使用文本优化模型；使用参考图或改图时应配置支持图片输入的模型，冷门角色外观查询还需要一个支持图片输入的模型。

## 配置

配置页面保留 API Key、图像模型、提示词优化模型、画质、尺寸、审核严格度、并发数、风格模式、风格强度和可选直接触发词。默认模型为 `openai/gpt-image-2.5-sunburst`，默认并发数为 3。插件固定使用官方 API 和 PNG 输出；主模型工具调用采用后台出图，关键词直出同步返回结果，并使用具有冗余的超时、重试和安全回退。改图输入支持 PNG、JPEG、WebP、GIF，单张本地输入按 Modelink 文档限制为 40 MB；输出接收上限为 80 MiB，为 4K PNG 留出余量。

## 开发验证

运行 `python -m unittest discover -s tests -v`。离线测试模拟 AstrBot 事件、模型及网络，覆盖外观渲染顺序与覆盖度校验、外观块是最终提示词字面子串这条不变量、优化器丢弃测试、五级安全回退后外观仍在、缓存命中与别名键、抽取的定向重试与拒绝、请求图片顺序、Provider 回退和网页读取限制，不调用真实绘图服务。

接口依据 AstrBot v4.28.0 的 `on_llm_request`、`ToolSet` 和 `Context.llm_generate(image_urls=...)`；工具 schema 在请求时显式补全嵌套对象。

以下三点只能联网实测，离线测试覆盖不到：

1. 主聊天模型是否会**自觉**调用 `prepare_character_reference`——这是整条链路的前提；
2. 视觉模型对冷门角色的抽取质量与偷懒率（日志会记录覆盖字段集与是否触发重试，便于统计）；
3. 冷门角色成图与参考图的相似度。

冷门角色外观查询还依赖 AstrBot 已配置的 Tavily 搜索；未配置时主模型搜不到资料页，插件会返回 `unavailable` 并明确要求不要编造外观。
